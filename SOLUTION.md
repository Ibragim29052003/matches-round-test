# Решение

## Сколько заняло

Около 15 минут на реализацию и первичные проверки с агентом. Личное знакомство кандидата с кодом в это время не включено.

## Что сделано и что не успел

Загрузка по HTTP, карточки, три фильтра, избранное, локальное время, состояния загрузки/ошибки/пустого списка, повтор и обновление. При ошибке обновления прежние данные и время последнего успеха сохраняются; запрос отменяется при размонтировании и через 15 секунд ожидания.

Дополнительно выбраны тесты логики фильтра: всего 19 проверок, включая формат ответа и часовые пояса. Проверен браузер; запуск на физическом телефоне и в нативном симуляторе не проверялся. Избранное, как и в шаблоне, хранится в памяти.

## Решения

- `scheduled` и `postponed` — «Предстоящие»: перенесённый матч ещё не завершён. `finished` — «Завершённые»; `live` и неизвестные статусы видны во «Все», чтобы не называть уже идущий матч предстоящим и не терять новые статусы API.
- Счёт `0:0` показывается; `null` не превращается в нули. Для отсутствующей или некорректной даты — «Дата уточняется»; `Intl.DateTimeFormat` без фиксированного `timeZone` использует пояс устройства. Статус берётся из API, а не вычисляется по дате.
- В исходном `MATCHES_URL` остались `OWNER/REPO`: подставлен HTTP-адрес данных исходного репозитория. Неверный JSON, повреждённая структура и дубли ID показывают ошибку, а не пустой список.
- Единственная новая runtime-библиотека — `react-native-safe-area-context`: учитывает вырез и системные панели, доступна в Expo Go. По документации SDK 57 уточнён минимум Node.js 22.13; по `expo install --check` применён патч Expo 57.0.30 в рамках того же SDK.

## Баги из части 2

1. Звёздочки: `indexOf` возвращает `-1` для отсутствующего ID (это truthy) и `0` для первого найденного (это falsy), поэтому `Boolean(indexOf(...))` давал неверный результат. `push`/`splice` меняли исходный массив, а `setFavorites` получал ту же ссылку — React мог пропустить перерисовку. Использованы `includes` и функциональный setter с новым массивом, чтобы быстрые нажатия работали с актуальным состоянием.
2. «Обновлено N сек назад»: интервал с `[]` захватывал начальный `seconds = 0` и каждый раз устанавливал `1`; `since` не использовался, а интервал не очищался. Теперь число секунд считается из `Date.now() - since`, эффект зависит от времени успеха и возвращает `clearInterval`: обновление сбрасывает подпись, задержки таймера не накапливаются.

## Как я использовал ИИ

Реализацию и первичную проверку выполнил Codex. Результат проверялся `npm run typecheck`, `npm test`, проверкой зависимостей Expo, production-экспортом web и в браузере: фильтры, отдельные звёздочки, ход и сброс таймера, медленный/пустой ответ, HTTP 503, повтор, неверный JSON и таймаут.

Исходные предположения дополнительно сверялись с реальностью: рабочий URL данных проверен HTTP-запросом, минимум Node.js — по документации именно Expo 57, необходимость патча — командой Expo. Подмена сети локальным API использовалась только для проверки; по умолчанию приложение обращается к исходному репозиторию.

## Что улучшил бы, будь ещё 2 часа

Регрессионные тесты хуков и жизненного цикла таймера, проверка в Expo Go на iOS/Android и со скринридером. Для реального продукта — согласование контракта неизвестных статусов и хранение избранного между запусками.
